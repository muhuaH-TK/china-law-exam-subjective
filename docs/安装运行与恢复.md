# 安装、运行与恢复接口 · 0.4.1

供桌面AI后台操作，普通用户只在聊天选择、提供资料与作答。证据须来自真实工具/界面，下面字段不是实际授权或回执。不通过清空PYTHONPATH、移除sitecustomize、安全垫片或取消审批来让测试通过。

## 首次项目选择与模式

优先创建专用桌面项目，再选本地目录并bootstrap；用户拒绝创建或当前无法完成可跳过，分别保存skipped/blocked。文件夹不等于桌面项目；以后补建关联原实例，不重置、不重复建任务。

桌面助手统一请求`{action,operation,payload,version}`，version须最新。onboarding的payload均含user_instruction：

自动创建受阻时读取guide(project)，由AI在聊天逐步引导用户手动创建。参考《用户手动创建项目指引.md》，先核对当前版本入口，完成后查真实名称、聊天归属和目录；不能创建或不愿创建仍可跳过，不猜项目ID、不依赖内部数据库。

正式与测试均先完成严格引导。context.experience.onboarding.steps返回逐项状态：unasked/confirmed/changed。配置默认值和已有资料不代表已询问；用户明确未定、暂不提供、拒绝安装也须保存真实回答。configure请求顶层须带user_instruction，所有入口均持久保存配置依据。先configure，再逐项answer，最后在聊天展示onboarding.summary并取得用户确认。

answer的payload为`{field,value,user_instruction}`。field依次包括year、participation、elective、selected_ai、timezone、authorization、automation、materials_course、sources、auxiliary_skills；前七项value须等于当前配置，后三项为用户选择的文本。不能用“已确认”替代未问的具体设置。明确未定的选做方向可通过，年度和是否参加须明确。资料可暂不提供，辅助技能可拒绝安装，但不能跳过询问。

最终start_formal或start_test携带当前summary_hash及用户对完整摘要的确认依据；测试实例也不得用合成预设代填选项。没有完整确认，程序阻止教学、运行和真实任务创建。旧实例不重置，只补实际缺项。设置变化会使相关回答失效，重读后只补变更项，再展示最新摘要确认。自动检索的考期不是用户选择，不把检索结果当新的用户确认。

每次成功返回的context已经包含最新version，顺序操作直接接续；版本冲突才重读、合并真实修改并受控重试一次。JSON用结构化工具参数或json.dump/json.dumps序列化，不手工转义原答。错误分别报告invalid_json、version_conflict、authorization_required、task_spec_mismatch等，不自动重放创建操作。

| operation | payload |
|---|---|
| project | status=pending/created/skipped/blocked；created另需真实project_id、name、tool、evidence；blocked需实际检查的tool、evidence |
| start_formal | summary_hash及用户对完整设置摘要的确认user_instruction；仅正式实例，项目选择不能pending |
| answer | field、value、该项用户真实回答user_instruction；前七项值与当前配置一致 |
| start_test | 独立测试实例完成与正式相同的全部引导，summary_hash及用户确认依据 |
| test_options | 仅测试实例；skip_materials、native_requested为布尔；启用临时任务须run_at为带时区ISO时间 |
| capability | capability=project/task_query/task_create/chat_create/chat_title/browser；method=native_tool/official_api/ui/tool_inventory；status=supported/failed/unavailable；tool、evidence；界面另需before_ref、after_ref |

能力按实际工具、官方受支持方式、可用界面逐层核查。缺少某工具不能推断整个平台不支持，也不能猜内部接口。界面操作前识别窗口/菜单、操作后回读；失败核对状态再受控重试，未确认结果保留缺项，不无限点击。

新实例usage_mode=setup，仅准备。年度已填、lifecycle=active都不能代替模式确认。旧实例缺mode也先补确认，保留原答、分数和日期。

测试使用`{action:"create_test",instruction:"真实测试指令"}`或MCP create_test_instance(workspace,user_instruction)，返回独立test_workspace。之后助手显式切换工作空间，MCP连接独立测试实例；不要继续把测试请求发往正式实例。原正式文件、绑定、答复、授权及任务不变。测试也逐项严格引导，不自动免教材、不自动采用合成设置；用户明确允许后可使用合成资料或暂免教材，真实文件仅按指定范围处理；测试实例不能start_formal。

正式实例完成全部逐项引导后，onboarding(start_formal)只需一次完整摘要确认，每日自动安排。正式第一阶段仍核验教材原题，无适配原题可unit_skip，不继承测试免教材。

## 原生任务对账

桌面action=automation，MCP automation_action；除claim/release外均需role和tool，所有操作需真实evidence。

1. claim唯一客户端与设备。工作空间必须绑定同一实例。
2. 实际查询宿主相关任务，reconcile(role,complete,candidates,tool,evidence)。失败用complete=false并保留错误，不把失败当空列表。候选只留相关元数据，不扫描无关聊天。
3. candidates每项`{task_id,enabled,spec}`，spec从真实宿主的工作目录、提示词、时区和调度结果解析，不复制当前计划填未知项。唯一匹配且规格一致恢复verified登记；漂移则update原ID。多匹配、身份缺失、查询失败均阻止创建。
4. 完整查询无匹配且无未决创建时，计划返回reserve_create；携带discovery_id调用同名操作，取得creation_id后才实际创建。该原子意图阻止并发重复创建。
5. record_task(role,task_id,status,tool,evidence,creation_id可选,observed可选)。created仅证明创建，仍须查询；verified必须有真实回读observed=`{task_id,enabled:true,spec}`且全规格一致；disabled须回读同ID、enabled=false及一致身份。failed不等于未创建。
6. 创建结果未知/回执保存失败时先对账找回，不再创建。完整新查询确证未创建且用户允许重试，才abandon_creation(user_instruction,...)后重试；不能盲撤意图。
7. 配置时间、时区、目录、项目或提示词变化会改fingerprint，是保护；先真实更新同一任务并回读，再登记，不能仅刷新回执。宿主查询发现意外漂移会使旧verified失效。
8. 迁移前真实停用并登记disabled，再release。学习/监测不同ID，测试/正式不同实例与模式。第一阶段monitor=wait正常；native_installed只汇总当前应安装角色，waiting_roles单列等待，不把等待当安装故障。

规范化spec须保留：

```text
instance_id role mode client device_id workspace data_dir idempotency_key
name timezone time rrule prompt host_project_id schedule_kind run_at
```

身份可从宿主真实保存的提示词、工作目录和设备信息提取。旧任务无模式时先请用户确认归属，真实更新明确标识后重新查询，不能猜。指纹本身不是规格证据。查询有效期15分钟且仅对应同一指纹；配置变化需新查。长期keep不等于到点验收，实际访问宿主发现变动时重新对账。

用户跳过专用项目时host_project_id不作必需条件，可保留客户端已有分组；不能因此把skipped改记created。用户已创建项目时则必须匹配该实际项目ID。

本地代码不控制宿主任务库，真实性依赖真实工具证据。无可查询接口或可靠界面时记录blocked，给出必要的一次性用户操作，不编造成功。

## 每日聊天与触发

正式任务名固定“法考每日学习”，每日新学习聊天名为当地日期YYYY-MM-DD；监测任务及固定维护聊天名“法考题源监测与维护”。测试任务/聊天带测试标识，不改名转正式。WorkBuddy日期运行会话也核验标题与归属；版本不支持时单列缺项。

桌面action=run，MCP run_action：

| operation | payload |
|---|---|
| begin | on当地当天、role=learning/monitor、trigger=chat/manual/scheduled、tool、evidence；原生触发需task_id，scheduled另需scheduler_event |
| record_chat | run_id、chat_id、实际title、实际project_id（已建项目时必需）、tool、evidence |
| finish | run_id、attempt_id、status=passed/failed/blocked、tool、evidence |

begin保留同日主运行及各次重试，返回expected_title与已关联聊天；同日重试续接，不重复生成主聊天或题量。跨日不能只重命名昨日聊天。项目已创建时实际project_id须吻合；跳过/受阻则不强制归组。

scheduled须真实调度事件`{trigger:"scheduled",event_id,scheduled_for,started_at}`，时间带时区，时刻吻合且实际开始不早于计划，归属当地当天。立即运行仅manual。finish前须实际聊天回读，通过后才生成对应触发验收；不把运行通过记成已学完，不补造答复。

测试任务默认不开，明确测试原生触发时仅一次run_at。运行后计划要求disable，AI实际停用并回读disabled后清除cleanup_required；失败保留待清理并提醒。

## 受控迁移

桌面action=migration，operation=prepare/execute/finalize/cancel；MCP migration_action另需当前workspace；payload均需真实user_instruction。

- prepare(target_workspace,target_data_dir可选)：目标不得已有绑定/数据，不与源实例嵌套；先核验旧任务disabled、无未决创建。旧运行器须正常停止并给runner_stopped_evidence。冻结源写入，保留迁移前instance，并完整备份、逐文件核验摘要。
- execute：核验备份与冻结后源资料未变，复制到新目标，保持实例ID、原件、原答和历史。核验目标绑定、重生成集成文件，保留源目录。新位置项目待核验，也可跳过；旧任务保持停用，再claim、对账同步。
- cancel：目标未绑定时恢复源可写，失败副本和备份保留，不删除、不自动重启任务。
- finalize：目标已绑定但源收尾中断时核验同一迁移ID并完成重定向，不恢复出两个可写实例。旧入口续接新位置，旧MCP须切换新数据目录。

复制失败不覆盖源或已有目标。本地execute只处理本机可访问目标，不声称已完成跨设备传输；跨设备须按用户允许方式传递完整核验备份，再在新端实际验证与绑定。无法自动完成的保留备份、原路径与恢复步骤，不靠手改三处JSON宣称成功。

## 分项验收

experience.checks按当前客户端、设备、模式和工作空间分开：source/environment/client_loaded/backend/binding/desktop_project/setup/native_task/manual_trigger/scheduled_trigger/import/question/correction/cross_day/monitor/export。无证据默认pending，跳过/受阻分别记。

桌面action=acceptance或MCP record_acceptance：check、status=passed/failed/blocked/skipped、kind=program/client、tool、evidence；客户端通过另需client_ref。源码/环境可用program，其他不以单测替代；scheduled_trigger只能由实际运行事件确认。客户端加载须新会话实际读取技能/后台证据，配置或下载包不足以证明。

client_loaded通过还需从实际客户端取得loaded_version，与当前包一致。验收保存software_version，升级后旧版通过事实保留在历史，但不冒充新版已验收。

doctor仅返回代码/依赖能力，不检查客户端、网络、权限或完整复习流程。可选依赖由AI按requirements-export准备并遵循正常审批。网络重跑通过只记重跑结果；年度考期必须实际官方检索，失败、未找到、未公布分开。实机学习、监测及PDF视觉未做则保留pending。
