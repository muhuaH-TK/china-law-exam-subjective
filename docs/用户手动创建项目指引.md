# 在聊天中引导用户创建桌面项目

正式与测试首次都先处理这一项。AI先核查真实工具、官方支持方式和当前界面；确实不能代建时，主动进入手动引导，不重复尝试同一失败方式。用户随时可以选择跳过。目录创建不等于桌面项目创建。

## 对用户说明

“请先在当前桌面应用新建一个专用复习项目。名称由你决定；测试请加‘测试’标识。创建后在项目内继续当前聊天或新建聊天，并选择同一本地复习目录。也可以选择暂时跳过，我会保留进度，之后再关联。”

先确认当前客户端与版本，再一次只指引一个可核验操作。看不到界面时让用户描述当前入口，不猜按钮位置、菜单名称或项目ID；不要要求用户执行命令、查数据库或填写配置文件。

## WorkBuddy

腾讯云官方的 **WorkBuddy Enterprise** 项目说明（2026-09-24更新）列出的路径为：客户端左侧“项目”→“+ 新建项目”→填写名称→“确认”。此路径只在当前版本界面对应时使用，不能假定个人版或其他版本入口一致。若没有项目入口，先依据当前官方说明与用户界面核查；仍没有时登记blocked或用户选择skipped。

项目内使用本地任务，并选择同一本地复习目录；工作空间是文件目录，不能当作客户端项目本身。不要默认把教材、作答上传到云端项目资产库。项目名称、任务归属及工作空间分别核验。

来源：[腾讯云：WorkBuddy Enterprise项目](https://cloud.tencent.cn/document/product/1831/138797)。使用前由AI核对实际版本；官方网页只是操作参考，不是本机已创建证据。

## Codex／ChatGPT桌面中的Codex

优先通过当前应用的项目列表核对已有专用项目，再根据当前官方说明或实际可见界面，引导用户选择新建项目、填写名称、关联本地文件夹。在项目中继续复习聊天。不同发行版本入口可能变化，不把历史“文件→New Project”菜单当作所有版本固定入口，也不把OpenAI API组织项目当作桌面复习项目。

如果当前界面无法核实，请用户描述项目入口；缺少可用创建工具时仍可由用户手动操作。不要因此要求用户重新下载源码、重建学习实例或自行编写命令。

## 创建后的核验与续接

1. 用实际宿主查询或可靠界面确认项目名称、当前聊天归属和所选本地目录。
2. 可取得真实项目ID时，onboarding(project)记录created、project_id、name、tool、evidence和用户依据。用户口头说“创建好了”不能伪造ID，也不代表后台已核验。
3. 用户已创建但暂时无法核验时，说明“项目待核验”，保留操作证据；按实际检查结果登记blocked，并在用户同意后先继续设置。不能冒记created，也不要不断要求重复创建。用户明确不建则登记skipped。
4. 后续能核验时关联原实例，不重置资料、授权或成绩。已有任务先对账，不能因补建项目另建重复任务。

项目选择完成后，仍须进行全部严格引导。创建项目、下载源码、加载技能、设置完成和真实定时触发是不同完成状态。
