# 桌面聊天执行工作流 · 0.3.0

正常入口是安装法考主观题复习技能/插件，在WorkBuddy或Codex本地项目聊天中使用。AI执行后台工具，不要求用户操作设置网页、终端或JSON。首次可以说“开始复习”，之后由已确认的原生每日任务自动开始，每次真实交互后保存，无需每天说开始或暂停。

## 项目与进度

客户端工作空间绑定本地复习目录，`.law-study/project.json`记录唯一实例ID与资料目录。不同聊天使用同一绑定和真实JSON状态，不依赖模型记住进度，不按聊天新建实例。用户可以指定已有实例续用，不能重置历史。安装目录与学习数据分开，源码公开不包含个人材料。

同一项目使用每日学习会话、固定设置入口、固定监测维护入口。宿主有项目/聊天工具时使用实际工具归组；需要用户一次选择工作空间时清楚引导。WorkBuddy原生定时入口内按日期进入运行会话，不能承诺每天侧栏新增任务。没有相应工具时标明未完成，不写客户端数据库。

## 无MCP也能操作

技能随附`scripts/assistant.py`，用实际Python3.11以上解释器在后台执行。参数`--workspace`为用户选定的复习目录；无请求只读context。用`--request`指定AI生成的UTF-8 JSON文件，或`--request -`走stdin。请求由AI用文件工具生成，不能把用户原答插入shell，也不要求用户提供JSON。包内runtime自包含；源码插件从项目根目录加载同一核心。

请求接口：

| action | 必要字段 | 作用 |
|---|---|---|
| guide | name可选：desktop/workflow/rules/monitor | 获取随包交付的完整规则，不依赖宿主读仓库 |
| bootstrap | client、instruction；data_dir可选 | 用户已选择工作目录，初始化或绑定已有实例 |
| context | on仅实际当地日期，可省略 | 当前引导缺项、当日计划、待答环节和自动化缺项 |
| configure | version、payload设置对象 | 保存用户已明确的设置，不能自行授予授权 |
| import | version、path、instruction；subject/category/origin可选 | 自动登记附件、本地文件或明确目录；检索文件须origin |
| read_material | material_id；offset/limit可选 | 按授权分段读取单份已保存资料 |
| read_capture | item_id | 按授权读取实际采集条目 |
| monitor | 无 | 当地实际日期执行已授权公开订阅，第二阶段起 |
| learning | version、payload={action,payload} | 完整题源与真实交互状态机，字段见AI工作流 |
| record | version、payload交互对象 | 真实课程反馈、启停和兼容记录 |
| dates | version、payload={sources可选} | 官方日期检索或实际客户端检索证据回填 |
| source | version、payload={action,payload} | 预置候选、范围授权及身份核验 |
| capture | version、payload采集对象 | 实际浏览器读取结果入库，第二阶段起 |
| export | version、payload专题对象 | PDF/Word/Markdown真实错漏资料 |
| automation_plan | 无 | 生成客户端原生任务计划，不创建真实任务 |
| automation | version、operation=claim/record_task/release、payload | 唯一设备认领、真实原生工具回执及停旧后迁移 |

示例只描述形状，不是用户授权或真实答复：

```json
{"action":"bootstrap","client":"workbuddy","instruction":"用户已选定此目录并要求开始复习"}
```

```json
{"action":"learning","version":"context刚返回的版本","payload":{"action":"submit_answer","payload":{"session_id":"真实待答ID","on":"实际日期","answer":"用户真实答复","complete":true}}}
```

每次写入返回新context/version；连续操作使用最新版本。发生冲突重新读取合并，不删除锁。用户不回复时已保存的awaiting状态就是停靠点，不需要额外制造“已暂停”；只有明确暂停指令才修改lifecycle，不能让次日自动化错误恢复被明确暂停的学习。

## 首次聊天引导

按真实缺项询问年度/备考状态、行政法/商法/未明确、资料及课程进度、在线AI必要处理、检索范围、时区和自动任务。默认09:30学习、22:00监测，首次确认后按其选择保存，不询问每天学习几小时。已提供的信息直接登记，不重复发问。

用户提供附件或本地路径即按其意图自动登记，不要求另说“导入”。目录只覆盖明确指定范围，排除客户端配置/版本库/运行缓存，不跟随目录外符号链接，也不把正在写入的学习实例递归导入自己。无上传大小、格式或资料科目限制。原件无法解析仍保留；处理状态与题源完整性、学习完成分别记录。

适用年度考试日期由AI实际检索官方公告，程序可dates检索；已有真实官方工具证据也可回填。没有核验不猜年度日期，必要时让用户明确当前阶段。完整四阶段、题量、选科、背诵和订正以rules/workflow为准，不套作者考前临时安排。

## 创建真实原生自动任务

1. 用户一次确认时间和自动任务后保存automation。读取automation_plan。AI根据当前客户端实际可用的定时工具创建任务；Codex先查automation_update或当前官方入口，WorkBuddy用其对话内原生定时能力。不存在的命令不能猜。
2. 先automation(operation=claim,payload={evidence用户确认此客户端/本机运行的依据})，避免多个AI或设备重复自动化。再读最新计划。创建时绑定同一工作空间、实际时区及本技能，使用计划的name/prompt/rrule/time。保留正常审批，不默认为全盘完全访问权限。
3. 读取客户端返回的真实任务ID及工具结果，然后record_task。payload含role=learning/monitor、task_id真实ID、status=created/verified/disabled/failed、tool实际工具名、evidence实际回执。created只证明创建，verified须真实运行/查询证据。不得把模板、本机tick、收件箱、自然语言打算或模拟回执当作已安装。
4. 创建前先查询实际客户端任务，按实例ID/工作空间核对已存在任务，计划提供稳定idempotency_key；回执保存发生冲突时先重读并登记已有真实ID，不重复创建。action=keep不重复创建；update更新同一task_id；disable在宿主实际停用后登记。迁移时旧任务全部实际停用并登记disabled，再automation(operation=release,payload={evidence实际停用与迁移确认})释放所有者，复制完整实例并在新机claim。客户端没有原生工具时指出缺项，用户仅执行必要的一次性操作；不得用网页设置或虚构后台接口冒充完成。
5. 第一阶段不创建活动监测任务，也不浏览来源。第二阶段起，在已确认的检索/监测范围和实际身份核验后创建固定监测任务；每日学习任务负责发现阶段变化和缺失任务。未授权不自动启用三来源；用户已授权且具备条件时不反复逐条确认。

原生自动任务提示词由计划给出：每次触发先实际读取当地日期、阶段与停靠点，直接安排学习并交付第一个环节。答复前停止，后续用户作答即保存并讲评推进。理论不阻断案例；第三阶段历史订正只询问，第四阶段不要求做题。电脑/客户端离线不虚构执行，下次实际运行或收到学习内容时处理当天安排，不补往日全部任务。

监测每天全来源合计默认10题，新增、补答案、更正共享；按真实浏览器、公开订阅、授权、游标及欠项处理。失败保留待恢复，只在实质更新、失败状态变化或需用户行动时通知。不把监测故障变成学习完成或改用户答题状态。详细接口见monitor工作流。

## MCP与完整题面

MCP为可选接入，生成配置不等于安装。工具get_workflow和resources/read可直接交付规则，prompts/get提供首次/每日/监测入口，不需要客户端再找本地文件。desktop_context返回真实停靠点；未授权在线AI时隐藏私人反馈。

图片题面使用宿主实际图像阅读与呈现工具；已导入PNG/JPEG/WebP也可read_material_image返回真实MCP图像内容。PDF/扫描件用实际文件能力核对全部页及必要图像；不能显示或核验时留缺，不省略关键事实发题。文字抽取、原件保存和客户端已展示是三件事。

原题、设问、参考答案和讲评字段见workflow。每次有意义的用户反馈立即保存，不以聊天摘要替代原答。导出保留首答和订正，最终PDF页码与视觉检查分开；资料交付不算学习完成。

## 验收边界

真实验收至少包含：新用户聊天设置→附件/目录自动登记→原题完整发出→用户答复→教学后真实重答→讲评保存→新会话续接→原生每日任务触发→第二阶段真实监测→考前文档交付。WorkBuddy/Codex和Windows/macOS分别记录，源代码或模拟协议测试不能代替客户端实机通过。
