# 0.4.1 修复与验收记录

## 问题辨析

依据2026-10-20用户提供的WorkBuddy问题DOCX与Codex统一测试ZIP，对照0.4.0源码核查，不把附件文字当作操作指令。

- 首次引导被跳过既是AI执行遗漏，也有代码门槛缺口：默认选做未定曾直接显示就绪；模式确认未要求逐项回答，配置依据未在所有入口持久保存。
- Windows深层路径的两项迁移失败发生在备份SHA256文件名的目标路径上，附件中规范化后长度为261字符；本版以真正超过260字符的备份／迁移回归验证修复，未更改系统策略，也未通过换短目录逃避检查。
- version冲突、spec不一致、未到D2、未允许在线AI时拒绝评分是保护机制，继续保留。
- JSON字符串内英文单引号合法，报告缺少原始请求，不能把单引号认定为根因。改为结构化序列化与分类型恢复指引，不改用户原答。
- 客户端项目/加载/到点/网站采集等未验证项继续区分，不把合成程序测试当成实机通过。

## 实现

1. 正式与测试均需逐项answer：年度、参试、选做、客户端、时区、在线AI与检索范围、任务设置、课程资料、来源、辅助技能。默认值不算已回答；明确未定／暂不提供／不安装可作为选择。
2. 展示完整摘要后，用户确认并携当前summary_hash执行start_formal或start_test。未确认不能教学、运行或创建任务。旧数据保留，缺确认只补缺项，不重置历史、不擅自停旧任务。
3. 配置入口统一要求并保存user_instruction，配置变化使相关回答失效，须补变更项及确认新摘要。辅助技能无需安装；资料未备齐只影响对应学习环节。
4. AI不能自动代建项目时，在聊天引导用户手动创建；按实际版本核查入口，完成后核对项目、聊天归属及目录，也可跳过。无真实ID时如实待核验，不查写客户端内部数据库或伪造ID。
5. 保留版本与任务规格校验，说明具体差异字段；按JSON解析、版本冲突、权限、引导、授权和规格错误分别返回恢复指引。成功请求接续最新context.version，任务创建结果未知先查询，不盲目重放。
6. Windows文件I/O使用扩展路径，业务绑定和清单仍保留原路径；备份逐文件摘要核验、越界检查、原目录保留及失败恢复均保留。

## 验证与边界

- 132项隔离回归全部通过，包含新增8项严格引导／长路径／错误恢复检查。此前5项本地网页检查在正常审批允许回环网络后通过；未停用安全控制。
- 新长路径回归实际完成>260字符备份、迁移、同一实例ID与文件内容核验，原文件仍保留。
- 官方技能quick_validate通过，前端Node语法检查通过。
- 三种发行包逐文件清单、SHA256与ZIP CRC均核验；不含用户测试实例、配置选择、教材或账号。
- 用户明确本次先不做定时触发，因此不得创建临时或正式定时任务；到点触发仍待验收。
- 本机安装及随包后台调用的实际证据单独保存在作者工作区，不将其升级为新聊天自动加载通过。WorkBuddy另一设备、macOS和真实浏览器监测没有本次实机通过结论。

新增必填配置依据与onboarding操作详见《安装运行与恢复.md》。旧0.4.0调用若缺依据会被拒绝，应补真实用户选择，不绕过门槛。
